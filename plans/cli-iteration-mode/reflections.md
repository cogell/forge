# Reflections: cli-iteration-mode

Append-only log of learnings discovered during implementation.

## Phase 3: forge run orchestration — two-layer changes

- **Worktree base-staleness is real.** Both 5.1 and 5.2 agents' worktrees forked from `main` (not from the `feat/cli-iteration-mode-phase-3` HEAD), confirming P0 of `forge-run-spec-changes.md`. Worktree branches showed phantom "deletions" of the Phase 3 plan files when diffed against `main`. Workaround: cherry-pick the worktree commits onto the feature branch instead of fast-forward merge. Three commits cherry-picked clean (5.1 + 5.2 original + 5.2 fix).
- **Hybrid execution (option 2 from the spec doc) worked.** 5.1 + 5.2 in parallel worktrees (genuine parallelism, no shared files), then 5.3 + 5.4 in-conversation (sequential dependency on 5.1 + 5.2's exports). End-to-end was clean and avoided the stale-base cherry-pick dance for the dependent tasks.
- **Mysterious cross-tree side effect.** After the 5.2 worktree-agent finished, the main repo's `src/commands/run.ts` and `src/commands/__tests__/run.test.ts` showed up STAGED (not just modified) with the agent's content. Cause unknown — may be Agent-tool worktree teardown propagating index back, or shared git index quirk. Workaround: `git reset HEAD` and `git checkout HEAD --` to clean before cherry-picking. Worth surfacing back upstream with a repro.
- **Locally-installed `forge` binary lags the codebase.** `--replace` flag added in Phase 1 (FORGE-3.7) wasn't recognized; `--phase` filter on `tasks ready` wasn't recognized. Editing `tasks.json` directly with Python is a reliable workaround, but reinforces that any task involving `forge tasks update --replace` will need the binary rebuilt first.
- **Multi-round external review caught issues that survived single-pass review.** Round 3 found two correctness gaps (diagnostic ownership ambiguity between query and CLI; missing `cwd` threading for subprocess tests) that rounds 1 and 2 missed. Round 4 was a verification pass and signed off. The pattern is now memorialized in agent memory as a feedback heuristic.
- **Injectable runner pattern (FORGE-5.3) avoided the fake-`.git/` precedent.** Eleven existing test fixture sites use a fake empty `.git/` directory which causes `git status --porcelain` to error and the catch to swallow into `false` — useless for testing dirty-detection. Exporting `GitRunner` + `defaultGitRun` + `detectDirtyPlanningArtifacts(feature, cwd, run = defaultGitRun)` made the helper testable with stub stdout, no real git fixtures needed. This pattern is reusable for any future subprocess-based detection.
